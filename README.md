# demo2 — Ship with AI 실습

이 저장소는 기존 실습과 분리하여 처음부터 진행하는 새로운 demo2 연습 공간입니다.

**AI Genius 시즌 5 에피소드 3 — AI로 완성하는 코드 리뷰부터 보안, 배포까지**를
GitHub 화면에서 순서대로 연습합니다. 안전한 한국어 사이트에 작은 기능을 추가하며
이슈 → Copilot 작업 → PR 리뷰 → 필수 검사 → 사람의 병합 → 배포를 확인합니다.

## 현재 상태와 출처

- 초기 사이트는 한국어 9개 페이지이며, 기존 테스트는 44개입니다.
- `src/pages/lesson.astro`와 탐색 메뉴의 **세션 요약**은 아직 구현하지 않았습니다.
  첫 실습에서 추가할 기능입니다. 취약점이나 가짜 시크릿을 심는 실습이 아닙니다.
- 문서 작성 시점의 로컬 `main`에는 커밋과 원격 저장소가 없습니다.
  가져온 소스 아카이브는 아래 출처 커밋과 동일한 상태에서 시작했습니다.
- 소스: [ijhan-biz/ship-with-ai-demo, 커밋 79d310030b681765f4a51050a11829d992c9d831](https://github.com/ijhan-biz/ship-with-ai-demo/commit/79d310030b681765f4a51050a11829d992c9d831)
- 원작: [anothergeorgecoldham/ship-with-ai](https://github.com/anothergeorgecoldham/ship-with-ai)

출처 저장소의 과거 PR·검사·배포는 demo2의 실행 기록이 아닙니다.
2026년 9월 28일 로컬 초기 검증에서는 Node 22.23.2로 테스트 44개 통과,
감사 취약점 0건, 페이지 9개 빌드를 확인했습니다. 새 에이전트 실행, 원격 설정, 배포는 수행하지 않았습니다.
감사 결과는 실행 시점에 달라지므로 취약점이 항상 0건이라고 보장하지 않습니다.

## 승인 후 별도로 준비할 항목

다음은 완료 기록이 아니라 **명시적 승인 후 수행할 설정 목록**입니다.

1. 포크가 아닌 독립 공개 저장소 `ijhan-biz/demo2`를 만들고, 안전한 초기 소스를
   `main`의 첫 커밋으로 게시합니다. 게시 전 `site`·`base`와 내부 링크가
   `https://ijhan-biz.github.io/demo2` 및 `/demo2/`에 맞는지 확인합니다.
   이 준비 과정에서 세션 요약 기능을 미리 구현하지 않습니다.
2. Pages의 Source를 **GitHub Actions**로 선택하고, `github-pages` 환경의
   배포 허용 브랜치를 `main`으로 제한합니다. 최초 배포를 실제로 확인합니다.
3. 새 저장소의 Copilot 이용 자격과 저장소·조직 정책을 확인합니다.
   소유자의 다른 저장소에 `copilot-swe-agent`가 있어도 새 저장소에서 이용 가능하다는 뜻은 아닙니다.
4. 자동 코드 리뷰 규칙 `copilot_code_review`를 별도로 설정합니다.
   새 푸시 리뷰는 `review_on_push: true`, 초안 PR 리뷰는 끔
   (`draft: false`라는 운영 의도)으로 준비합니다.
   이는 원격 API 필드나 설정 적용을 검증했다는 기록이 아닙니다.
5. `main` 변경은 PR을 거치고 우회 병합을 허용하지 않도록 설정합니다.
   필수 `build` 검사는 `npm ci` → 테스트 → high 수준 감사 → 빌드와
   매니페스트·잠금 파일 변경 검사를 포함해야 합니다.
   1인 실습에서는 필수 승인 리뷰 수를 **0**으로 설정하고 실제 리뷰 대화 해결을 요구합니다.
   본인 PR에 대한 자체 승인을 필수 승인으로 계산하지 않습니다.
6. CodeQL은 별도 선택 설정입니다. 구성한 경우에만 해당 검사 결과도 확인합니다.
   일반 GitHub **Allow auto-merge**도 원하는 경우에만 허용합니다.
   Agent Merge와 다르며, 자동 병합 예약 전에도 사람이 변경과 필수 검사 성공을 확인해야 합니다.
7. **처음부터 실행하는 데모** 이슈 템플릿을 준비했는지 확인합니다.
   **세션 요약 페이지 추가: 이슈에서 배포까지** 이슈는 담당자 없이 준비하고,
   기존 준비 이슈가 있으면 중복 생성하지 않습니다.

출처의 Dependabot 설정(npm 매일, GitHub Actions 매주)은 그대로 유지합니다. 서버 측 보안 업데이트 및 자동 수정의
자동 활성화는 아직 하지 않았습니다. 필요하면 주요 설정을 마친 뒤 별도로 검토하세요.
실습 중 관련 PR이나 알림이 추가될 수 있습니다.

## 실습 범위

새 페이지는 기존 `Layout`을 사용하며 **코드 리뷰, 보안 게이트, 승인 후 배포**의
세 주제를 간단히 정리합니다. 탐색 메뉴 **세션 요약**은 `/demo2/lesson/`으로 연결하고,
본문에는 **이슈에서 배포까지 연결했습니다.**를 표시합니다.

이번 작업은 기능 추가에 한정합니다. 보안 코드, 의존성, `package-lock.json`,
기존 테스트, CI와 Dependabot 설정은 변경하지 않습니다.
필요한 기능 테스트만 기존 도구로 추가합니다. 피드백은 브라우저에만 저장되며
서버나 발표자에게 전송되지 않는 기존 동작을 유지합니다.

## 선택 사항: 로컬 검사

GitHub 화면을 기본으로 사용합니다. CLI가 필요하면 demo2 작업 폴더에서
Node 22 계열 **22.12 이상**을 사용하세요. 사용할 수 있는 검증용 버전은 **22.23.2**입니다.
아래 명령으로 다시 확인할 수 있습니다. `git diff` 검사는 초기 파일을 커밋한 뒤에 유효하며,
아직 추적하지 않은 파일의 무변경을 증명하지는 않습니다.

```bash
npm ci
npm test
npm audit --audit-level=high
npm run build
git diff --exit-code -- package.json package-lock.json
```

잠금 파일은 변경하지 않습니다. 오류를 없애기 위해 `npm install`이나 `npm audit fix`를
실행하지 말고 원인을 확인하세요. 초기 기준은 테스트 44개와 페이지 9개이며,
기능 추가 후에는 새 페이지와 필요한 추가 테스트도 확인합니다.
감사 통과는 모든 보안 위험이 없다는 뜻이 아닙니다.

실제 연습 순서, 확인 지점과 문제 해결은 [RUNSHEET.md](./RUNSHEET.md)를 따르세요.
